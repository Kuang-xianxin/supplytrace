# 实现与面试要点

这个产品的数据流是：CSV原件入库→严格解析→用户选候选键→后台分组→原行对照→人工意见→历史和导出。主流程使用FastAPI、Pydantic、SQLite、原生ES模块；模型只做可选建议，不承担数量判错或去重授权。

1. **业务身份不等于内容相同。** 同订单同SKU可以分两次到货；12与8不同不证明错误。候选键只是把待核对行放在一起，最终原行永远保存。面试问题：为什么不能直接groupby后取max或drop_duplicates？
2. **SQLite上下文不等于关闭连接。** Python的sqlite连接上下文主要处理提交/回滚，必须额外close。本次ClosingConnection让退出作用域就释放句柄。面试问题：为什么单次请求正常、长时间运行却可能积累资源？
3. **版本号防止覆盖，幂等键防止重复。** 两人同时基于revision0保存，只有一个成功，另一个409；同一次请求重试则返回已保存结果，不加新事件。二者解决的问题不同。面试问题：请求超时后到底是否保存了，为什么不能直接生成新ID重试？
4. **停止任务还需要代次隔离。** 旧任务收到停止后可能仍在执行；新任务已经开始时，旧线程不能再把结果写为ready。每次处理generation增加，最后写入也核对generation。面试问题：取消Future为什么不等于正在运行的函数已停止？
5. **WAL解决读写协调，不提供多实例产品能力。** 一个本机进程能受益于读写并行，但团队帐号、工作区权限、网络部署和数据库恢复仍是独立要求。面试问题：什么时候才该迁移PostgreSQL？
6. **备份不是直接复制活动数据库。** WAL里可能存在已提交数据；backup API得到一致快照，随后完整性检查、计数和新目录恢复才构成证据链。面试问题：文件SHA相同为什么不等于业务恢复正确？
7. **前端草稿与服务器记录分工。** 已保存批次与意见在数据库；尚未保存理由留当前浏览器。语言切换不翻译用户原文；页面路由代次防止旧异步响应覆盖新页面。面试问题：localStorage能否当可靠主数据库？
8. **输入安全和可追溯性同时成立。** 导出的派生CSV会转义公式前缀，原CSV与JSON仍保留原值并明确格式。面试问题：为什么不能悄悄清洗原数据然后只保留清洗结果？

验证学习：测试不只数通过数量。检查合法多行没有丢失、错误文件原件仍可下载、同批并发只有一个写入、源文件和导出字节相同、恢复到新目录能重新打开结果。具体命令见根目录 README，已测边界见 VERIFICATION-20261027.md 和 INTEGRATIONS.md。

9. **输出格式正确不等于推理正确。** 本轮真实模型可以输出合法JSON却无依据声称“数据有效”。JSON schema解决括号、字段和引用范围；系统指令改善行为；独立语义评估仍不可省略。面试问题：为什么通过Pydantic/JSON schema验证的答案仍不能自动执行采购或去重？
